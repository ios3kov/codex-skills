# Local OpenAI documentation workflow

This offline reference preserves the workflow when the documentation service is unavailable. It is not a frozen price list or a claim about current model availability, limits or account settings.

1. Identify product, exact task, installed SDK/CLI version and available host tools.
2. Inspect local SDK types, CLI help, configuration schema and project examples before selecting an API. Preserve credentials and account settings. Do not auto-install a documentation connector merely because a source link fails.
3. When online, use available official documentation tools, then official OpenAI websites where needed. Verify live model/price/limit/account claims from the relevant authoritative surface. A local note cannot establish today's quota.
4. When offline, answer the stable part supported by local evidence; show the inspected version and date. Mark version-sensitive or account-dependent facts UNVERIFIED and explain the missing check. Do not invent an endpoint, model ID, tool or successful request.
5. Keep citations traceable. Source URLs are credits/update locations; they are not a runtime dependency for this preserved method.

Responses supports response-oriented input/output and tool workflows in SDK versions that expose it; Chat Completions uses message-based completions. Realtime handles interactive streaming sessions. Actual SDK signatures and events must come from the installed version. A conceptual description is not permission to send private data, change credentials, grant access or incur a paid request.
