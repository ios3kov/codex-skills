## Refero

The upstream README says live research requires a paid Refero plan. The methodology works with inspected user references, live web evidence, and the incumbent system without that service.

- Styles: visual-system metadata for web marketing/product pages.
- Screens: concrete interface/state patterns, including operational and native screens.
- Flows: connected task steps and system responses.

Search previews are leads. Retrieve full style/screen/flow details for finalists. Raw screen images answer visual questions that metadata cannot. At the inspected version, style coverage is not a dashboard/auth/native style-system catalog; do not force marketing evidence into those contexts.

If results are weak, broaden a query, change the axis, inspect another result page, or use adjacent task examples. Reconstructed journeys remain proposals. Tool names and argument details should come from discovery, not copied MCP setup commands or this document.

## Scenario

The upstream workflow combines the team's assets, a public catalog, user preferences, and open-web references. Owned assets can have the best brand fit; still verify their actual reuse rights. Public visibility and ability to copy a file do not prove a license for use in deliverables.

Where the current schema exposes semantic/keyword search and positive/negative image seeds, use them to answer different questions. The inspected version used `query_semantic_ratio` values near `0` and `0.8`; do not assume those parameters exist elsewhere. Count actual returned/inspected assets, not an estimated total.

A collection is optional persistence. Creating it or uploading outside/private assets must follow the authorized task and permissions. Resolve asset ownership and existing membership before adding. The upstream reported failures for foreign assets and duplicate IDs; these are historical observations to verify, not universal API contracts. Metadata/tag replacement can lose prior data: inspect current behavior and preserve existing fields.

For generation, discover the model's schema, reference types/count, and actual file-ID requirements. A style image does not guarantee exact brand color, type, placement, or identity. Hand off compact role-specific inputs and keep exact typography/logo work in the appropriate editable/compositing workflow.

## Open web and local evidence

Use available search and browser tools. Follow user/browser constraints; there is no inherited universal “in-app only” restriction. Search text for named techniques as well as images, then visually inspect finalists.

Live sites, supplied screenshots, collections, museums, and open-license catalogs serve different purposes. Check source-specific access and licensing when relevant. Do not treat old claims about blocked sites, free searches, or download behavior as verified-current facts. If permitted access fails, record the source gap and use another source; no brittle access workaround is needed to fill a slot.

Do not install another provider, start a subscription, create an automation, or run a paid generation job merely to make this research skill function. Use the capabilities appropriate to the task's existing authorization; generation/production belongs to its own workflow.

## SHOOOT

Optional reference: [shoootai.com](https://shoootai.com/) for image/video prompt ideas, camera angles, focal lengths, camera moves and visual styles. Use when the task needs one of these choices, not for every design task. Browse relevant categories and inspect the full example; do not assume a working search API or indexed web results. Adapt the technique to the subject, shot purpose and target tool, preserving the source link and distinguishing site examples from results actually tested. If access fails or examples do not help, continue with other sources. Existing research, source-rights and output-review rules still apply; the site is not a required dependency.
