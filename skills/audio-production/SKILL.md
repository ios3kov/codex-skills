# Audio production

For offline use and external-reference handling, read [local resources](references/offline-resources.md).

Make audio support the message and picture. Determine whether the request is a sound plan, generated/source assets, an actual mix or an encoded delivery before selecting tools.

- Read [sound spotting and Foley](references/sound-spotting.md) for ambience, materials, perspective, meaningful effects and transitions.
- Read [mix and delivery](references/mix-and-delivery.md) for balance, source repair, processing, stems, loudness and listening verification.

Inspect the actual picture, script and available audio/stems. Establish duration, fps/timebase, voice/music/effects hierarchy, output channels, intended playback context and requested files. Keep an authoritative audio contract or pointer; use existing project conventions and preserve source recordings.

Choose targets from the actual client/platform/broadcaster specification. A production heuristic can support a labeled rough mix when no target is given. Do not treat a streaming normalization value as a universal mastering specification, or select the loudest reference as the target.

Use only available documented sound-generation or editing tools. This instruction skill does not install a sound provider, DAW, loudness meter or upstream helper script. When execution is unavailable, complete the useful sound plan and identify the checks still unperformed.

Use `motion-storytelling` for the picture's rhythm and musical cut positions. This skill owns audible events, mix hierarchy and output audio checks; use `media-production-control` for the shared asset/version record. For AE or Remotion integration retain audio boundaries and stems rather than flattening revisions prematurely.

Report planning separately from generated assets, mix processing, loudness measurement and actual listening. Successful export or a waveform is not evidence that speech is intelligible. Verify each delivered encoding whose audio properties matter.
