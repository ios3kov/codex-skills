# Identity application

Use for a requested identity system or its application, not to redesign an established logo during routine layout work.

Connect the mark to the established palette, type roles, image language, shape vocabulary and actual touchpoints. Strategy/factual promises come from the brief or [brand positioning](shared/editorial-copy/references/brand-positioning.md). Shared type rendering stays with [typography](shared/interface-craft/references/typography.md); mark construction stays in [logo design](logo-design.md).

Distinguish canonical logos/named variants from surrounding graphics. Place an approved lockup as an asset rather than rebuilding its spacing/lettering. Recoloring, containers, textures and effects follow actual brand permissions; do not impose universal bans or silently invent variants.

Present useful relationships: mark/lettering, color, type and applications relevant to the audience. Use readable exact text and faithful assets. Choose format, panel count, density and light/dark presentation from the deliverable, not a mandatory cinematic 3 × 3 board. A flattened brand board is a presentation, not a vector master, complete guideline package or working product.

Show requested applications rather than generating every possible card, app icon, billboard and dashboard. Label fictional/demo placements; do not invent clients, behavior or market evidence. Existing UI/collateral workflows own responsiveness, accessibility, page/stage layout, print preflight and export.

Record source/version pointers, palette/medium, font requirements, named variants and exceptions in established project records. Reuse asset manifests/guidelines. If a missing variant is necessary, create a scoped derivative within authorized design work and check it; preserve the master.
